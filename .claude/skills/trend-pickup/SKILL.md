# トークテーマのピックアップ

X と Threads で直近に伸びた投稿を集め、Mai さん（5児のママ経営者・日本×ドバイ3社代表）の
Instagram リール用トークテーマを10本にまとめる。

## 進め方

### 1. 収集条件を決める

既定は「直近30日 / いいね1,000件以上」。ユーザーの指定があればそちらを優先する。

### 2. 候補URLを集める（discovery）

`APIFY_TOKEN` があるかどうかで経路が変わる。

**ある場合** — こちらが本番の経路。

```bash
node trend/discover.mjs --provider apify --days 30 > /tmp/candidates.txt
```

**ない場合** — WebSearch で代用する。ただし検索インデックスは数週間遅れるので、
直近1ヶ月の投稿はほとんど引っかからない。**この制約はレポートに必ず明記する**。

`trend/lib/themes.mjs` の `THEMES` にあるキーワードを組み合わせ、
`allowed_domains: ["threads.com"]` と `["x.com"]` で10〜15本ほど検索する。
結果から投稿URL（`/post/<code>` と `/status/<id>` を含むもの）を抜き出して
1行1URLのファイルにする。プロフィールURLやタグページは混ぜない。

### 3. 実数を取って絞り込む

```bash
node trend/collect.mjs --urls /tmp/candidates.txt --days 30 --min-likes 1000 \
  --out data/$(date +%Y-%m-%d).json
node trend/report.mjs data/$(date +%Y-%m-%d).json > data/$(date +%Y-%m-%d).md
```

いいね数・投稿日時は埋め込みの公開エンドポイントから取った**実測値**。
ここで出た数字を推測で埋めたり丸めたりしない。0件なら0件と報告する。

条件通過が10件に満たないときは `--keep-all` で全件を見て、
何が落ちたか（期間か、いいね数か、テーマか）を確認してから相談する。
**足りない分を推測で埋めない。**

### 4. トークテーマ10本に落とす

`data/<日付>.md` を読み、以下の観点で10本を選ぶ。

- 賛否が割れているか（コメント欄が伸びている投稿ほど良い）
- Mai さんの立場で語れるか。特に強い接続点は次の5つ：
  - 経済的自立 ―「夫に文句を言う前に自分で稼ごう」
  - 期待しない哲学 ―「期待するから不満が出る。初めから期待しない」
  - 頼ることへの寛容さ ― ドバイではナニー・家政婦が当たり前という日本との対比
  - 修羅場の実績 ― 借金1,300万・離婚・ステップファミリー・5児・40歳で出産
  - 他責から自責へ ―「環境のせいにして止まっている女性」への問いかけ
- テーマが5カテゴリに散っているか（育児／夫婦／妊活・出産／女性の働き方／ジェンダー）

各テーマにつき次を書く。

1. **見出し** — 元投稿の主張を一文で
2. **元投稿** — @ユーザー名／プラットフォーム／投稿日／いいね数／URL（すべて実測値）
3. **議論のポイント** — なぜ伸びたか、どこで賛否が割れているか
4. **Mai さんの切り口** — 上の5つの接続点のどれで語るか、具体的に3〜5行
5. **フック案 3本** — 提案書のフック変換3原則に沿って
   - 「あなた」への宣告に変える（体験談の主語を視聴者に向ける）
   - 仮想敵の行動を冒頭で指摘する
   - 逆説・断言・禁止で違和感をつくる

   例：「旦那の収入に期待してる女性は人生墜落します」「お母さんは頑張るな」

### 5. 出力

`data/<日付>-talk-themes.md` に書き出し、要点をチャットにも返す。
Google ドキュメントに入れる指定があれば Google Drive のツールで作成する。

## やってはいけないこと

- いいね数・投稿日・ユーザー名を推測で書く。取れなかったものは「取得できず」と書く
- 条件を満たす投稿が足りないときに、古い投稿を直近のものとして混ぜる
- ログインが要るページを突破しにいく。使うのは公開の埋め込みエンドポイントだけ
