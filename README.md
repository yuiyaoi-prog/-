# クライアント運用状況 確認オペレーション自動化

MAGI-C の「クライアント別 月次報告MTG / 撮影 / インナーMTG 日程管理」スプレッドシートを軸に、
クライアントの運用状況の社内確認を自動化する Google Apps Script プロジェクト。

- 設計の経緯・調査結果・決定事項 → [`docs/implementation-plan.md`](docs/implementation-plan.md)

## できること

| 機能 | 実行タイミング | 概要 |
|---|---|---|
| カレンダー同期 | 毎日 10:00 | 矢追友唯のカレンダーの予定を、月別シートの「前回実施日／次回予定日」へ自動反映 |
| 撮影日程アラート | 毎月25日 10:00 / 毎週水曜 10:00 | 撮影の「次回予定日」が空欄のクライアントを Slack へ通知 |

## ファイル構成

```
src/
  appsscript.json   マニフェスト（タイムゾーン・OAuthスコープ）
  config.gs         全設定。列レイアウトを変えたらここを直す
  util.gs           正規化・日付整形・セル統合・クライアント読み取り
  calendarSync.gs   カレンダー同期
  shootAlert.gs     撮影日程の未確定アラート
  triggers.gs       トリガー設定
```

## セットアップ手順

### 1. スプレッドシート側の準備

**① D列を別名リストにする**

イベントタイトルの表記揺れを吸収するため、D列にカンマ区切りで別名を列挙する。
（例：カレンダー上は `撮影 RAT` だがシートは `パーソナルジムRAT` のため、そのままでは一致しない）

| 行 | クライアント | D列に入れる値 |
|---|---|---|
| 5 | よし子先生Podcast | `よし子先生Podcast,よし子先生,よし子` |
| 6 | ちきゅうのうたげ | `ちきゅうのうたげ,地球のうたげ` |
| 7 | ボンボンクリニック（渋谷） | `ボンボンクリニック_渋谷,ボンボン渋谷,角野` |
| 8 | ボンボンクリニック（横浜） | `ボンボンクリニック_横浜,ボンボン横浜,村石` |
| 9 | パーソナルジムRAT | `パーソナルジムRAT,RAT` |
| 10 | KINSプライム（下川さん） | `KINSプライム,KINS` |
| 11 | シースタンド | `シースタンド,シースタ` |
| 12 | NAS（スポーツクラブ） | `NAS` |

比較時に半角/全角スペースの除去・全角英数の半角化・大文字小文字の無視を行うので、
`撮影_よし子先生 Podcast` のようなスペース入りの表記も一致する。

**② 行3のグループ見出しを埋める（推奨）**

現状、行3の E〜M（月次報告MTG / 撮影 / インナーMTG のグループ見出し）が空欄で、
3組ある「次回予定日」の区別が人間にもつかない状態になっている。
`E3:G3` `H3:J3` `K3:M3` にそれぞれ見出しを入れることを推奨する。

> スクリプト側はブロックの並びを `config.gs` の `CONFIG.BLOCKS` で持っているため、
> 見出しが空でも動作する。並びが違っていた場合は `BLOCKS` の `kind` の順序だけを入れ替える。

### 2. Slack の準備

1. Slack App を作成し、**Bot Token Scopes に `chat:write`** を追加してワークスペースにインストール
2. 発行された Bot User OAuth Token（`xoxb-` で始まる）を控える
3. Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に
   キー `SLACK_BOT_TOKEN` として保存
4. **Bot を `#03_pm-ディレクター管理` に `/invite` する**
   （プライベートチャンネルのため、招待しないと `not_in_channel` で送信に失敗する）

チャンネルID `C0BL1HELL3B` は `config.gs` に設定済み。

### 3. カレンダーの権限

`config.gs` の `CALENDAR_ID` は `256yui@gmail.com`（撮影・MTGの実データが入っている個人カレンダー）。
スクリプトを実行するアカウントがこのカレンダーを参照できる必要がある。
別アカウントで実行する場合は、Google カレンダーの共有設定で閲覧権限を付与すること。

### 4. 動作確認 → 本番化

1. **`dryRunCalendarSync()` を実行**（シートには書き込まない）
   - 実行ログで、どのクライアントのどのセルが更新されるかを確認する
   - 「クライアントに紐付かなかった予定」のログを見て、D列の別名リストを追記する
   - `RAT` `NAS` `KINS` は短いため誤検知しやすい。ここで必ず目視確認すること
2. `syncCalendarToSheets()` を実行して実際に書き込む
3. `testRunNow()` で Slack 通知の疎通を確認する
4. **`setupTriggers()` を1回実行**して自動実行を有効化（初回は権限承認が必要）
5. `listTriggers()` で3本登録されたことを確認する

## 判定ロジック

### クライアントの特定

イベントタイトルを正規化し、D列の別名がタイトルに含まれるかで判定する。
複数のクライアントが該当した場合は、**一致した別名がより長いほう**を採用する。

### 種別の判定

上から順に評価し、除外ルールに当たったものはその時点で対象外にする。

| 順序 | 条件 | 結果 |
|---|---|---|
| 1 | `撮影前` `撮影について` `撮影の件` `撮影日程` を含む | **対象外** |
| 2 | `インナー` を含む | インナーMTG |
| 3 | `月次` を含む | 月次報告MTG |
| 4 | `撮影` を含む | 撮影 |
| 5 | いずれにも該当しない | 対象外 |

除外ルールは、`東大恋愛YouTube 撮影前MTG` や `社外_ボンボンクリニック様 横浜村石先生撮影について`
のような「撮影に関する打ち合わせ」を撮影として誤検知しないために必要。

### 書き込み

- イベント**開始日**が属する月のシート（`8月` `9月` …）に書き込む → 月跨ぎはこれで解決
- 本日より前 → 「前回実施日」／本日以降 → 「次回予定日」
- 複数件は `8/5, 8/20` のようにカンマ区切りで1セルに列記
- 既存の手動入力値は**上書きせず統合**する（同一日付は重複させず、日付順に並べ替える）
- 日付として解釈できないメモ書きはセル末尾にそのまま残す

## clasp で管理する場合

```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json   # scriptId を実際の値に書き換える
clasp push
```

`scriptId` は Apps Script エディタの「プロジェクトの設定」→「スクリプト ID」から取得する。
