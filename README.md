# クライアント運用状況 確認オペレーション自動化

MAGI-C の「クライアント別 月次報告MTG / 撮影 / インナーMTG 日程管理」スプレッドシートを軸に、
クライアントの運用状況の社内確認を自動化する Google Apps Script プロジェクト。

- **セットアップ手順（初めての方はこちら）** → [`docs/setup-guide.md`](docs/setup-guide.md)
- 設計の経緯・調査結果・決定事項 → [`docs/implementation-plan.md`](docs/implementation-plan.md)

## できること

| 機能 | 実行タイミング | 概要 |
|---|---|---|
| カレンダー同期 | 毎日 10:00 | 矢追友唯のカレンダーの予定を、月別シートの E列「月次報告日」・F列「次回撮影日」へ自動反映 |
| 撮影日程アラート | 毎月25日 10:00 / 毎週水曜 10:00 | F列「次回撮影日」が空欄のクライアントを Slack へ通知 |

「2026年8月」シートには2026年8月の予定、というように、**シート名の月と同じ月の予定だけ**が
書き込まれます。シート名は `2026年8月` と `8月` の両方に対応（年を省略した場合は今日に
一番近い年として解釈）。月別シートは何枚あっても構いません。

## シートの前提

| 列 | 内容 | スクリプトの扱い |
|---|---|---|
| A | クライアント名 | 読む（`▼`・`（例）` 始まりの行はスキップ） |
| B | PM | 読まない |
| C | 担当ディレクター | 読む（Slack通知の「担当」に使う） |
| D | カレンダー検索キーワード | 読む（カンマ区切りの別名リスト） |
| E | 月次報告日 | **書き込む** |
| F | 次回撮影日 | **書き込む**／アラートの判定対象 |
| G | ステータス | 触らない（手動運用） |
| H〜M | 未使用 | 触らない |
| N | 備考 | 触らない |

データ開始行は5行目。

## ファイル構成

```
src/
  appsscript.json   マニフェスト（タイムゾーン・OAuthスコープ）
  config.gs         全設定。列レイアウトを変えたらここを直す
  util.gs           正規化・日付整形・セル統合・年の解決
  calendarSync.gs   カレンダー同期
  shootAlert.gs     撮影日程の未確定アラート
  checkSetup.gs     セットアップ診断（何も変更しない）
  triggers.gs       トリガー設定
dist/
  all-in-one.gs     src/ を1ファイルに結合したもの（Apps Scriptに貼る用・自動生成）
test/
  verify.js         判定ロジックの回帰テスト（node test/verify.js）
tools/
  build-all-in-one.js  dist/all-in-one.gs の生成スクリプト
```

`src/` を編集したら `node tools/build-all-in-one.js` で `dist/` を再生成すること。
`node tools/build-all-in-one.js --check` で最新かどうかだけ確認できる。

## 関数早見表

|---|---|---|
| `checkSetup` | 設定を診断する | 安全（何も変えない） |
| `dryRunCalendarSync` | 同期結果を予告する | 安全（何も変えない） |
| `listTriggers` | トリガー一覧を表示 | 安全（何も変えない） |
| `syncCalendarToSheets` | シートに日付を書き込む | シートが変わる |
| `testRunNow` | Slackに今すぐ通知を送る | Slackに投稿される |
| `setupTriggers` | 自動実行を設定する | トリガーが作られる |

## 判定ロジック

### クライアントの特定

イベントタイトルを正規化（全角英数→半角、スペース除去、大文字化、さらに
`_` `-` `・` `（）` `【】` などの区切り記号を除去）し、D列の別名がタイトルに
含まれるかで判定する。別名 `ボンボンクリニック_渋谷` でカレンダーの
`ボンボンクリニック渋谷` を拾えるのはこのため。
複数のクライアントが該当した場合は、**一致した別名がより長いほう**を採用する。

なお種別の判定には区切り記号の除去を適用しない。詰めてしまうと
`撮影 - 前田さん` が `撮影前` と誤判定されてしまうため。

D列の別名リストは**全シートを合算**して使う。1枚のシートに入っていれば全シートで有効なので、
5枚のシートに同じ内容をコピーする必要はない。

現在の別名リスト：

| クライアント | D列の値 |
|---|---|
| よし子先生Podcast | `よし子先生Podcast,よし子先生,よし子` |
| ちきゅうのうたげ | `ちきゅうのうたげ,地球のうたげ` |
| ボンボンクリニック（渋谷） | `ボンボンクリニック_渋谷,ボンボン渋谷,角野` |
| ボンボンクリニック（横浜） | `ボンボンクリニック_横浜,ボンボン横浜,村石` |
| パーソナルジムRAT | `パーソナルジムRAT,RAT` |
| KINSプライム（下川さん） | `KINSプライム,KINS` |
| シースタンド | `シースタンド,シースタ` |
| NAS（スポーツクラブ） | `NAS` |

### 種別の判定

上から順に評価し、除外ルールに当たったものはその時点で対象外にする。

| 順序 | 条件 | 結果 |
|---|---|---|
| 1 | `撮影前` `撮影について` `撮影の件` `撮影日程` を含む | **対象外** |
| 2 | `インナー` を含む | インナーMTG（書き込み先が無いので何もしない） |
| 3 | `月次` を含む | 月次報告MTG → E列 |
| 4 | `撮影` を含む | 撮影 → F列 |
| 5 | いずれにも該当しない | 対象外 |

除外ルールは、`東大恋愛YouTube 撮影前MTG` や `社外_ボンボンクリニック様 横浜村石先生撮影について`
のような「撮影に関する打ち合わせ」を撮影として誤検知しないために必要。

### 書き込み

- シート名の月と同じ月の予定だけを、そのシートに書き込む
- **本日以降の予定のみ**。過去の予定は書き込まない
- 複数件は `8/5, 8/20` のようにカンマ区切りで1セルに列記
- 既存の手動入力値は**上書きせず統合**する（同一日付は重複させず、日付順に並べ替える）
- **過ぎた日付はセルから取り除く**（`CONFIG.PRUNE_PAST_DATES`）。
  E列・F列は常に「これから先の予定」だけになる。撮影が終わって次が未定になると
  F列が空になり、撮影アラートで拾われる
- 日付として解釈できないメモ書き（`未定（調整中）` など）は削除せず末尾に残す

シート名に年が無い場合（`8月`）は「今日に一番近い年」を選ぶ。12月時点で「1月」シートを
見たときは翌年の1月として扱う。

## clasp で管理する場合

```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json   # scriptId を実際の値に書き換える
clasp push
```

`scriptId` は Apps Script エディタの「プロジェクトの設定」→「スクリプト ID」から取得する。
