# セットアップ手順書（Slack / Apps Script）

初めての方向けに、クリックする場所まで書いています。
**上から順にやれば終わります。所要時間はだいたい20分です。**

全体の流れ：

```
STEP 1  Apps Script にコードを貼る        （3分）
STEP 2  Slack App を作ってトークンを取る   （10分）
STEP 3  トークンを Apps Script に登録      （3分）
STEP 4  診断して動作確認                   （5分）
STEP 5  自動実行をONにする                 （2分）
```

---

> **シート側の準備は完了しています。**
> D列の別名リストは入力済みです。別名は全シートを合算して使うので、
> 5枚のシートに同じ内容をコピーする必要はありません。

---

## STEP 1. Apps Script にコードを貼る

### 1-1. エディタを開く

1. 日程管理スプレッドシートを開く
2. 上のメニューから **「拡張機能」→「Apps Script」** をクリック
3. 新しいタブで「無題のプロジェクト」というエディタが開く
4. 左上の「無題のプロジェクト」をクリックして、**`クライアント日程管理`** など分かりやすい名前に変更

> スプレッドシートから開くと、そのシートに紐づいたスクリプトになります。この方法が一番簡単です。

### 1-2. コードを貼り付ける（1ファイルだけ）

**[`dist/all-in-one.gs`](../dist/all-in-one.gs) を貼るだけです。** ファイルを分けて作る必要はありません。

1. エディタの中央に `コード.gs`（または `Code.gs`）が開いている
2. その中身（`function myFunction() {}` という雛形）を **全部消す**
   - エディタ内をクリック → **Ctrl+A（Macは Cmd+A）** → **Delete**
3. `dist/all-in-one.gs` の中身を**全部コピーして貼り付け**
4. **Ctrl+S（Macは Cmd+S）** で保存

エラー表示が出なければ STEP 1 は完了です。

> `dist/all-in-one.gs` は `src/` の6ファイルを結合した自動生成ファイルです。
> 中身は同じなので、どちらの方法でも動作は変わりません。

### 1-3. タイムゾーンを確認する

トリガーの「10:00」はスクリプトのタイムゾーンで解釈されます。ここがズレていると
別の時刻に動いてしまうので、確認しておきます。

1. 左メニューの **歯車アイコン（プロジェクトの設定）**
2. **「タイムゾーン」** が **「(GMT+09:00) 日本標準時 - 東京」** になっているか確認
3. 違っていたら変更する

> 後で実行する `checkSetup` でも自動チェックされるので、ここは飛ばしても構いません。

## STEP 2. Slack App を作ってトークンを取る

Slackに自動投稿するには「Bot（ロボットのメンバー）」を作る必要があります。

### 2-1. Appを作る（マニフェストを使う方法・推奨）

設定ファイル（マニフェスト）を貼り付けるだけで、名前も権限も一発で設定されます。

1. ブラウザで **https://api.slack.com/apps** を開く
   （MAGI-CのSlackにログインしているアカウントで開いてください）
2. 右上の **「Create New App」** をクリック
3. 「Or start your own way」の **「From a manifest」** を選ぶ
4. ワークスペース `MAGI-C` を選んで **「Next」**
5. **JSON** のタブを選び、入力欄の中身を全部消して、
   [`slack-app-manifest.json`](../slack-app-manifest.json) の中身を貼り付ける

   ```json
   {
     "display_information": {
       "name": "撮影日程アラート",
       "description": "撮影日程が未確定のクライアントを 03_pm-ディレクター管理 に通知します",
       "background_color": "#2c2d30"
     },
     "features": {
       "bot_user": {
         "display_name": "satsuei-alert",
         "always_online": false
       }
     },
     "oauth_config": {
       "scopes": {
         "bot": [
           "chat:write"
         ]
       }
     },
     "settings": {
       "org_deploy_enabled": false,
       "socket_mode_enabled": false,
       "token_rotation_enabled": false
     }
   }
   ```

6. **「Next」**→ 内容の確認画面が出るので **「Create」**

これで権限（`chat:write`）まで設定済みのAppができます。**次は 2-3 に進んでください。**

> `chat:write` は「メッセージを投稿する」権限です。これ1つだけでOKです。
>
> `display_name` が `satsuei-alert` とローマ字なのは、この項目が Slack の
> ユーザー名（@ハンドル）に変換されるため**日本語が使えない**からです。
> 日本語を入れると `The display_name cannot be converted to a username` という
> エラーになります。チャンネルに表示される見た目の名前は、App作成後に
> 左メニュー「App Home」→「Edit」から日本語に変更できます。

### 2-2. （マニフェストを使わない場合）手動で作る

2-1 でうまくいかなかったときだけ、こちらを実施してください。

1. 「Create New App」→ **「Blank app」**（以前の「From scratch」にあたるもの）を選ぶ
2. **App Name**: `撮影日程アラート` / **Pick a workspace**: `MAGI-C` →「Create App」
3. 左メニューの **「OAuth & Permissions」** をクリック
4. 下にスクロールして **「Scopes」** セクションを探す
5. **「Bot Token Scopes」**（※すぐ上の「User Token Scopes」ではない方）の
   **「Add an OAuth Scope」** をクリック
6. 検索欄に `chat:write` と入力して選択

### 2-3. ワークスペースにインストールしてトークンを取得

1. 同じページの一番上までスクロール
2. **「Install to Workspace」**（または「Install to MAGI-C」）をクリック
3. 確認画面が出るので **「許可する」** をクリック
4. 画面が戻り、**「Bot User OAuth Token」** という欄に
   `xoxb-` で始まる長い文字列が表示される
5. **「Copy」** ボタンでコピー（この後すぐ使います）

> ⚠️ このトークンはパスワードと同じです。Slackやメールに貼らないでください。

### 2-4. Botをチャンネルに招待する

**これを忘れると必ず失敗します。**

1. Slackアプリで **`#03_pm-ディレクター管理`** を開く
2. メッセージ入力欄に次を入力して送信

   ```
   /invite @satsueialert
   ```

3. 「satsueialert がチャンネルに参加しました」と表示されればOK

> このチャンネルは**プライベート**なので、招待しないとBotは投稿できません。

## STEP 3. トークンを Apps Script に登録

1. Apps Script のタブに戻る
2. 左メニューの **歯車アイコン（プロジェクトの設定）** をクリック
3. ページ下部の **「スクリプト プロパティ」** セクションへ
4. **「スクリプト プロパティを追加」** をクリック
5. 入力する
   - **プロパティ**: `SLACK_BOT_TOKEN`
     （前後にスペースが入らないよう注意）
   - **値**: STEP 2-3 でコピーした `xoxb-...` を貼り付け
6. **「スクリプト プロパティを保存」** をクリック

> コードに直接トークンを書かないのは、GitHubなどに流出させないためです。

## STEP 4. 診断して動作確認

### 4-1. 診断を実行する

1. 左メニューの **`< >`（エディタ）** に戻る
2. 上部中央の関数プルダウン（`myFunction` などと表示されている箇所）から
   **`checkSetup`** を選択
3. **「実行」** をクリック

### 4-2. 初回だけ出る「承認」画面

初回は必ず権限の確認が出ます。怖い画面ですが正常です。

1. **「権限を確認」** をクリック
2. 自分のGoogleアカウントを選択
3. **「このアプリは Google で確認されていません」** と出たら
   → 左下の **「詳細」** をクリック
   → **「（プロジェクト名）（安全ではないページ）に移動」** をクリック
4. 権限の一覧が出るので **「許可」** をクリック

> 自分で書いたスクリプトなのでこの警告が出ます。Google審査を受けていない、という意味です。

### 4-3. 結果を読む

画面下の **「実行ログ」** に診断結果が出ます。こんな形です。

```
===== セットアップ診断 =====

■ タイムゾーン
OK  Asia/Tokyo（日本標準時）

■ スプレッドシート
OK  「クライアント別日程管理」に接続できました
    シート一覧: 日程管理 / 2026年8月 / 2026年9月 / 2026年10月 / 2026年11月 / 2026年12月
OK  同期対象の月別シート 5枚:
    2026年8月 → 2026年8月の予定を取得します
    2026年9月 → 2026年9月の予定を取得します
...
■ Slack
OK  Slackに接続できました（ワークスペース: MAGI-C / Bot: satsueialert）
```

**`NG` が1つもなければ次へ進んでください。** `NG` があれば末尾のトラブル対応表を見てください。

### 4-4. カレンダー同期を「お試し実行」する

いきなりシートに書き込むと怖いので、まず**書き込まないモード**で確認します。

1. 関数プルダウンから **`dryRunCalendarSync`** を選択
2. **「実行」** をクリック
3. 実行ログに「どのセルがどう変わるか」だけが表示されます

```
対象シート: 2026年8月 / 2026年9月 / 2026年10月 / 2026年11月 / 2026年12月（ドライラン：書き込みません）
[2026年8月] シースタンド / 次回撮影日: 「」→「8/12」
[2026年8月] NAS（スポーツクラブ） / 次回撮影日: 「」→「8/7」
[2026年8月] ドライラン（書き込みなし）：更新対象 2件
[2026年8月] クライアントに紐付かなかった予定 3件（D列の別名リストに追加を検討してください）:
  8/9 撮影_花森先生 Podcast（あいりちゃん対応）（種別:撮影）
```

ここで確認すること：

- **月別シートが全部「対象シート」に出ているか**（2026年8月〜2026年12月）
- **変な日付が入ろうとしていないか**（特に `RAT` `NAS` `KINS` は3〜4文字と短いので、
  関係ない予定を拾っていないか）
- **「紐付かなかった予定」に、本当はシートに入るべきものが混ざっていないか**
  → 混ざっていればD列の別名を追加（どれか1枚のシートに入れればOK）
- **消えようとしている日付がないか**
  E列・F列は「これから先の予定」だけを残す仕様なので、
  過ぎた日付は自動で取り除かれます。`「8/5, 8/20」→「8/20」` のようなログが出たらそれです

### 4-5. 本番の書き込みとSlack送信

問題なければ実行します。

1. 関数プルダウンから **`syncCalendarToSheets`** → 「実行」
   → シートに日付が入ります
2. 関数プルダウンから **`testRunNow`** → 「実行」
   → Slackに実際にメッセージが飛びます

---

## STEP 5. 自動実行をONにする

1. 関数プルダウンから **`setupTriggers`** を選択
2. **「実行」** をクリック
3. 実行ログに次が出れば完了です

```
トリガー設定完了：
  ・カレンダー同期  毎日 10:00
  ・日程アラート    毎月25日 10:00（翌月分）
  ・日程アラート    毎週月・水・金曜 10:00（当月分）
```

確認したいときは **`listTriggers`** を実行すると一覧が出ます。
左メニューの **時計アイコン（トリガー）** からも確認・削除ができます。

**以上で完了です。以降は自動で動きます。**

## トラブル対応表

| 症状 | 原因 | 対応 |
|---|---|---|
| `NG トークンが無効です: invalid_auth` | トークンの貼り間違い | STEP 3 をやり直す。前後の空白に注意 |
| Slack送信エラー: `not_in_channel` | Botをチャンネルに招待していない | STEP 2-4 の `/invite` を実行 |
| Slack送信エラー: `channel_not_found` | チャンネルIDが違う、またはBot未招待 | STEP 2-4 を実行。それでも出たら連絡ください |
| Slack送信エラー: `missing_scope` | `chat:write` の付け忘れ | STEP 2-2 の後、**再度 Install to Workspace が必要** |
| `NG カレンダーにアクセスできません` | 実行アカウントに共有されていない | ログに出る「現在の実行アカウント」に、`256yui@gmail.com` のカレンダーを共有する |
| `NG 月別シートが1枚もありません` | シート名が違う | シート名を `2026年8月` または `8月` の形式に合わせる |
| 入れたはずの日付が消える | 過去日は自動で取り除く仕様 | 過去も残したい場合は `config.gs` の `PRUNE_PAST_DATES` を `false` に |
| `!! 別名がクライアント名とかけ離れています` | D列の入れ違い | 該当行のD列を確認 |
| 同期しても何も入らない | 別名がイベント名と一致していない | `dryRunCalendarSync` のログの「紐付かなかった予定」を見て別名を追加 |
| 「このアプリは Google で確認されていません」 | 自作スクリプトのため正常 | 「詳細」→「安全ではないページに移動」→「許可」 |

## 各関数の役割（早見表）

| 関数名 | 何をするか | 危険度 |
|---|---|---|
| `checkSetup` | 設定を診断するだけ | 安全（何も変えない） |
| `dryRunCalendarSync` | 同期結果を予告するだけ | 安全（何も変えない） |
| `listTriggers` | トリガー一覧を表示 | 安全（何も変えない） |
| `syncCalendarToSheets` | シートに日付を書き込む | シートが変わる |
| `testRunNow` | Slackに今すぐ通知を送る | Slackに投稿される |
| `setupTriggers` | 自動実行を設定する | トリガーが作られる |

困ったら、まず **`checkSetup`** を実行してログを見てください。
