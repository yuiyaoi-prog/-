## 2. 確定した設計

### 2-1. アラート対象

> **決定（2026/07/27）**: 契約状況列は新設せず、**シートに行があるクライアントは全て対象**とする。
> 契約終了時は行を削除する運用。

判定条件：
- A列（クライアント名）が空でない
- A列が `▼` / `（例）` で始まらない
- 撮影ブロックの「次回予定日」が空欄 → アラート対象

### 2-2. D列の別名リスト仕様

D列に**カンマ区切り（全角・半角どちらも許容）**で別名を列挙する。
マッチングは「イベントタイトルにいずれかの別名が部分文字列として含まれるか」。
比較前に、タイトル・別名の双方を正規化する：

- 全角/半角スペースを除去
- 全角英数 → 半角
- 大文字小文字を無視

投入する別名リストの初期案（実カレンダーの出現形から作成）：

| クライアント | D列に入れる値 |
|---|---|
| よし子先生Podcast | `よし子先生Podcast,よし子先生,よし子` |
| ちきゅうのうたげ | `ちきゅうのうたげ,地球のうたげ` |
| ボンボンクリニック（渋谷） | `ボンボンクリニック_渋谷,ボンボン渋谷,角野` |
| ボンボンクリニック（横浜） | `ボンボンクリニック_横浜,ボンボン横浜,村石` |
| パーソナルジムRAT | `パーソナルジムRAT,RAT` |
| KINSプライム（下川さん） | `KINSプライム,KINS` |
| シースタンド | `シースタンド,シースタ` |
| NAS（スポーツクラブ） | `NAS` |

※ `RAT` `NAS` `KINS` は短く誤検知リスクがあるため、初回テスト時にヒット結果を目視確認する。

### 2-3. 種別判定ルール

別名リストとは独立に、イベントタイトルから種別を判定する。**除外判定を先に評価する。**

1. **除外**（どの列にも書かない）: タイトルに `撮影前` / `撮影について` / `撮影の件` を含む
2. **インナーMTG**: `インナー` を含む
3. **月次報告MTG**: `月次` を含む
4. **撮影**: `撮影` を含む（1で除外されなかったもの）
5. いずれにも該当しなければスキップ

### 2-4. 書き込みルール

- イベント**開始日**の属する月のシート（`8月` `9月` …）に書き込む → 月跨ぎはこれで解決
- 実行日より過去の日付 → 「前回実施日」列
- 実行日より未来の日付 → 「次回予定日」列
- 同一セルに複数件ある場合は **`8/5, 8/20` のようにカンマ区切りで列記**（決定済み方針）
- カレンダー由来と手動入力の区別はしない（決定済み）
- 手動入力値の扱い：カレンダー由来の日付を**統合**する（既存値を丸ごと消さない）。
  同一日付は重複させず、日付順にソートして書き戻す
