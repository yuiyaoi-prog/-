# トークテーマ自動ピックアップ

X と Threads でバズった投稿を集め、Mai さんの Instagram リール用トークテーマに
落とし込むための仕組み。参考にした資料は次の2つ。

- トークテーマ資料（Threads バズ投稿30件の分類）
- INSTAGRAM Maiさん ブラッシュアップ提案書（仮想敵・フック変換の3原則）

## 使い方

```bash
# 1. 候補URLを集める（Apify を使う場合）
node trend/discover.mjs --provider apify --days 30 > /tmp/candidates.txt

# 2. いいね数・投稿日時の実数を取って絞り込む
node trend/collect.mjs --urls /tmp/candidates.txt --days 30 --min-likes 1000 \
  --out data/2026-08-05.json

# 3. 人が読める形にする
node trend/report.mjs data/2026-08-05.json > data/2026-08-05.md
```

Claude Code からは `/trend-pickup` で 1〜3 とテーマ10本への絞り込みまで通しで走る。
Node 18 以上があれば動く。npm パッケージへの依存はない。

テストは `node trend/test/verify.mjs`。ネットワークを使わない。

## 仕組み

**「投稿を見つける」と「いいね数を知る」は別問題**で、使える手段がまったく違う。
ここが分かるとこの仕組みの形が理解しやすい。

| | 手段 | 費用 |
|---|---|---|
| いいね数・投稿日・本文を知る | 公開の埋め込みエンドポイント | **無料・鍵不要** |
| 投稿を見つける（検索） | Apify / 公式API / 人力・Claude の検索 | ここだけ課金か審査が要る |

いいね数のほうは、X も Threads も「埋め込み表示」用の公開エンドポイントを持っていて、
ログインも API キーもなしに正確な数字が取れる。

- Threads … `https://www.threads.com/@user/post/<code>/embed`
- X … `https://cdn.syndication.twimg.com/tweet-result?id=<id>`

問題は検索のほう。Threads の検索ページもプロフィールページもログイン必須で、
サーバー側では中身を返してくれない。だから discovery だけ差し替え可能にしてある。

> 実装メモ：Meta は「ブラウザのページ遷移に見えるリクエスト」にしか中身のあるHTMLを返さない。
> `Sec-Fetch-Mode: navigate` を付けないと空のJavaScriptシェルが返ってきて何も読めない。
> `lib/fetchers.mjs` の `NAVIGATION_HEADERS` がそれ。

## discovery をどうするか（3案）

「直近1ヶ月」という条件を素直に満たせるかどうかが分かれ目になる。

### 案A：Apify（推奨）

Threads / X 用のスクレイパを従量課金で借りる。RECENT 検索ができるので直近1ヶ月を素直に満たせる。

- 費用：1,000件あたり 0.5〜1 USD 程度。月1回の運用なら**月に数百円**
- 準備：Apify に登録 → API トークンを発行 → `APIFY_TOKEN` に設定するだけ。審査なし
- 弱点：非公式スクレイパなので、提供元の都合で仕様が変わることがある
  （`APIFY_THREADS_ACTOR` で別アクターに乗り換えられるようにしてある）

### 案B：Meta 公式 Threads API

`/keyword_search` エンドポイントで、`since` / `until` を指定した検索ができる。

- 費用：無料。1日2,200クエリまで
- 準備：Meta 開発者アプリを作り、**`threads_keyword_search` 権限の審査を通す**必要がある
- 弱点：**公式APIは他人の投稿のいいね数を返さない**。
  なので「検索は公式API、いいね数は埋め込み」という組み合わせで使う。
  この組み合わせなら全部無料で、かつ規約上もっとも安全
- Threads だけ。X には同等の無料経路がない

### 案C：検索エンジン経由（鍵なしで今すぐ動く）

Claude Code の WebSearch で `threads.com` / `x.com` を絞り込み検索し、
出てきた投稿URLを `collect.mjs` に流す。

- 費用：0円。準備なし
- 弱点：**検索インデックスが数週間〜数ヶ月遅れるため、直近1ヶ月の投稿はほとんど拾えない**。
  2026年8月時点で実際に試したところ、拾えた50件のうち直近45日以内は3件だけだった。
  「バズった投稿を広く見る」用途には使えるが、「直近1ヶ月」の条件は満たせない

### まとめ

| | 直近1ヶ月を満たせるか | 費用 | 準備 |
|---|---|---|---|
| 案A Apify | ○ | 月数百円 | トークン発行のみ |
| 案B 公式API＋埋め込み | ○ | 無料 | 審査に数日〜数週間 |
| 案C 検索エンジン | ✕ | 無料 | なし |

**まず案Aで回し始めて、案Bの審査が通ったら乗り換える**のが現実的。
X は案Aしか選択肢がない（公式APIは従量課金に一本化され、全期間検索は
Enterprise 契約が要るため、月1回の用途には見合わない）。

## ルーティン化

月1回・毎月1日に流すなら、Claude Code の Routine を作って
「`/trend-pickup` を実行して結果を Slack に投げる」を登録するのが一番手数が少ない。

`data/` に日付ごとのJSONとMarkdownが残るので、
同じテーマが何度もバズっているか（＝繰り返し使える鉄板ネタか）も後から追える。

## テーマを変えるとき

`lib/themes.mjs` だけ直せばいい。コードは触らなくていい。

- `THEMES` … 拾う対象のテーマとキーワード
- `BRAND_SIGNALS` … Mai さんの発信軸に刺さる語（加点され、上位に来やすくなる）
- `EXCLUDE` … 落としたい話題（SNS運用ノウハウ、稼ぐ系の勧誘など）

## 制約

- 使うのは公開の埋め込みエンドポイントだけ。ログインが要るページは取りにいかない
- 返信のURLを渡すと、埋め込みはスレッドの先頭から描画する。
  その場合いいね数は元投稿のものになり、`metricsFromThreadRoot: true` の印が付く
- 画像・動画だけの投稿は本文が取れず、テーマ分類から漏れる。
  レポートの「テーマ未分類」欄に出るので、目視で拾う
- Threads 埋め込みの日時にタイムゾーンの表記がないため UTC として扱っている。
  月単位の判定には影響しない
